# Media pipeline

## 1. Сессия

Twitch status берётся из Helix, w.tv — из profile/channel API. Offline ставит `endedAt`, но session остаётся `live` 30 минут. Reconnect внутри окна очищает `endedAt`; после окна status становится `ended`. Без active/grace session сообщение не создаёт `ChatPost` или `DownloadJob`.

Worker проверяет очередь загрузок каждые 5 секунд независимо от внешних опросов. До четырёх каналов w.tv опрашиваются одновременно. После завершения опроса канал снова доступен через 5 секунд. У запросов к w.tv и раскрытия коротких ссылок канала общий дедлайн 15 секунд на опрос. Если у канала уже есть очередь повторных попыток, worker сохраняет новую страницу с медиассылками до обработки этой очереди. Запись `messages=100/100` в журнале означает, что страница чата заполнилась до лимита API. Профили Twitch обновляются при старте и затем раз в час. После ошибки worker повторяет обновление при следующем опросе.

Опрос каждого источника завершает его сессии с известным `endedAt` старше 30 минут, в том числе при недоступности API. Отдельная задача закрывает такие сессии удалённых из конфигурации каналов и удаляет записи повторных попыток w.tv для завершённых сессий. При остановке worker отменяет запросы к API, закрывает Twitch IRC и EventSub, дожидается уже принятых событий и активной очереди загрузок, затем отключает PostgreSQL.

## 2. Фильтры

До извлечения URL отбрасываются:

- `!sr` в начале сообщения;
- отдельный маркер `catAsk`;
- авторы `Nightbot`, `StreamElements`;
- w.tv markers `GSS-media`, `ME-*`.

Сообщение с `!skip_tg` получает флаг `skipTelegramPublic=true`. Медиа сохраняется в Telegram storage, а исходный текст — в БД. Публичные канал и бот пропускают это сообщение.

Если из сообщения w.tv успела сохраниться только часть ссылок, при повторе worker берёт исходную подпись, автора и признак приватности из архива. Worker проверяет архив по ID до фильтрации новой копии сообщения. Добавленная позже метка `!skip_tg` распространяется на сохранённые ссылки и ожидающие попытки, в том числе после перезапуска. Для принятого медиасообщения worker сохраняет ID, исходную сессию и признак приватности даже после очистки очереди. Повтор этого ID в следующем эфире игнорируется, в том числе при изменении `createdAt`.

## 3. URL и безопасность

Поддержка:

- jpg/jpeg/png/gif/webp/avif, mp4/webm/mov;
- Discord CDN без расширения;
- Twitch Clips, TikTok, YouTube watch/Shorts/youtu.be, публичные Instagram Reels (`instagram.com/reel/...` и `/reels/...`);
- Postimages, ImgBB, eblo.id, Yandex Disk `/i/...` и `/d/...`;
- `clck.su`, `clck.ru`, `bit.ly`, `tinyurl.com` с поддерживаемым target.

Нормализация убирает fragment/default port, приводит hostname к lower-case, канонизирует Twitch Clips/Yandex Disk/Instagram Reels, чистит Discord query params. Варианты Reels с `www`, без завершающего slash и с tracking query приводятся к `https://www.instagram.com/reel/<id>/`, чтобы не сохранять ролик повторно.

Все redirects и DNS addresses проходят SSRF-защиту: только HTTP(S), без localhost/private/local/reserved IP. `ALLOW_PRIVATE_MEDIA_HOSTS=true` отключает DNS-проверку; в production не использовать без причины.

## 4. Очередь и дедупликация

Проверки: blocked normalized URL, stored asset по URL, скачивание/SHA-256, blocked SHA, stored asset по SHA. Повтор переиспользует Telegram message.

Для медиа из w.tv worker ставит публичную отправку в очередь PostgreSQL в той же транзакции, которая сохраняет пост со статусом `stored`. Это правило действует и для новой загрузки, и при совпадении URL или SHA-256. Отправка в публичный канал идёт отдельно от опроса чатов. Перед каждой группой до 10 файлов worker проверяет приватность и остановку. При явном временном отказе Telegram группа возвращается в очередь. Подтверждение отправки начинает 48-часовое окно дедупликации. Повторные ссылки в этом окне пропускаются до занятия слота Telegram. Если процесс аварийно завершился между резервированием группы и подтверждением отправки, эта группа может быть пропущена. Остаток альбома продолжится после истечения резерва (10 минут).

При прямой загрузке worker контролирует размер по мере чтения HTTP-ответа. SHA-256 он вычисляет один раз для каждого готового файла после нормализации или перекодирования. Этот хеш используется для проверки блокировок, поиска дубликатов и записи в `Asset`.

Jobs забираются через `FOR UPDATE SKIP LOCKED`; SHA lock не даёт двум слотам сохранить одинаковые bytes. Максимум 3 попытки: первые две возвращают `pending` с задержкой, третья ставит job/post/asset в `failed`. Дневной лимит считает stored bytes после полуночи worker.

## 5. Скачивание и обработка

Прямое медиа: HEAD, затем streaming GET с byte counter. Defaults: 30 MiB image, 100 MiB video.

`yt-dlp`: без playlist, до `MAX_PLATFORM_VIDEO_SECONDS` (default 300), проверка известного размера до скачивания, итоговый MP4. Age-restricted YouTube использует `/run/private/youtube-cookies.txt`.

Instagram Reels используют тот же путь при `ENABLE_PLATFORM_DOWNLOADS=true`. Если платформа не сообщает длительность, скачивание разрешено в пределах byte limit; перед обработкой/публикацией длительность проверяется через `ffprobe`. Слишком длинный файл или файл без определяемой длительности отклоняется. Профили, фото-посты и аудио-страницы не поддерживаются; закрытые и требующие входа ролики могут быть недоступны. Instagram cookies не настроены.

Telegram normalization:

- GIF/animated WebP конвертируются в MP4 и отправляются через `sendAnimation`;
- фото resize/pad через ImageMagick;
- видео конвертируется в H.264/yuv420p + AAC с `faststart`;
- видео больше 49.9 MB сжимается two-pass;
- `ffprobe` добавляет width/height/duration.

## 6. NSFW

Worker проверяет новые медиа перед отправкой в storage и сохраняет флаг спойлера для публикации в публичном канале. [Правило, выборка кадров и история моделей](nsfw.md).

## 7. Telegram

Файл сначала отправляется в private storage с streamer/session/asset/SHA-256/URL; Telegram IDs сохраняются в `Asset`.

Worker выделяет два общих слота для `ffprobe` и создания обложек видео перед отправкой в Telegram. Одиночные видео и все альбомы используют один лимит. Worker передаёт в Telegram параметры уже проверенного файла. После перекодирования он читает параметры итогового файла. Если обложку получить не удалось, видео уходит в своей позиции без обложки.

Публичный канал получает медиа, если канал настроен, пост и стример публичны, asset видим и истекло окно дедупликации предыдущей отправки.

Публичный бот заново проверяет доступность каждого поста перед копированием из storage. При ответе HTTP 429 или 5xx он повторяет текущий запрос. Если соединение оборвалось после запроса и результат копирования неизвестен, бот завершает начатую страницу, чтобы избежать дублей.

```text
#streamer_stream #date_YYYY_MM_DD #user_sender
```

Текст без URL добавляется после `:`; без текста colon отсутствует. Caption до 1000 символов, дата `Europe/Moscow`.

## 8. Deleted messages и moderation

EventSub `channel.chat.message_delete` сопоставляется с временным `TwitchChatMessage`. Buffer живёт `TWITCH_CHAT_MESSAGE_RETENTION_MINUTES`; `DeletedChatMessage` хранится постоянно. Private/hidden/`!skip_tg` не публикуются.

Admin-бот скрывает asset или удаляет из storage. Удаление ставит `deleted + hidden` и блокирует URL/SHA, предотвращая повторное сохранение.
