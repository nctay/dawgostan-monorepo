# Domain docs

Use one root CONTEXT.md as the project glossary and docs/adr/ for decisions. A multi-context layout is unnecessary for the current scope.

Before exploring a feature, read the glossary and any relevant ADRs. Missing files do not block work. Use the glossary's canonical terms in specifications and tickets; flag conflicts with existing ADRs. Domain modeling updates the glossary as terms are resolved and creates ADRs only for consequential trade-offs.
