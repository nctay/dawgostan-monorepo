# Варианты NSFW-классификатора для Telegram-архива

Проверено 2026-09-26. Цель: уменьшить ложные спойлеры при локальном CPU inference на VPS 2 vCPU / 4 GB. Цифры точности из карточек моделей относятся к их собственным наборам данных, не к нашему архиву.

## Сейчас и возможность дообучения

- В prod работает `andresribeiroo/nsfwjs:3.1` с лимитом 1 CPU / 512 MB. Worker отправляет до 8 кадров видео и ставит спойлер, когда **максимум** `Porn`/`Hentai` по любому кадру ≥ 0.7; при ошибке тоже ставит спойлер ([compose](../../docker-compose.prod.yml), [worker](../../apps/worker/src/services/nsfw.ts)). Порог нельзя переносить на другую модель без новой калибровки.
- NSFWJS загружает готовую TensorFlow.js модель и даёт 5 классов: `Drawing`, `Hentai`, `Neutral`, `Porn`, `Sexy`. Само дообучение делается вне Docker API: исходный [nsfw_model](https://github.com/GantMan/nsfw_model#tf1-training-folder-contents) содержит скрипты transfer learning / fine-tuning MobileNetV2 и InceptionV3, затем модель нужно экспортировать для TensorFlow.js и подменить загружаемые файлы. Исходный обучающий датасет не опубликован ([автор](https://github.com/GantMan/nsfw_model#extra-info)). Лицензии исходной модели и NSFWJS — MIT ([модель](https://github.com/GantMan/nsfw_model/blob/master/LICENSE.md), [библиотека](https://github.com/infinitered/nsfwjs/blob/master/LICENSE)). Для нескольких ошибок переобучение пока не обосновано: нужны размеченные положительные и отрицательные примеры и отложенная проверка по видео.

## Короткий эксперимент до смены prod

Локальный пробный прогон 2026-09-26: NudeNet 3.4.2 на восьми кадрах пользовательского ролика (26.7 с) не обнаружил `*_EXPOSED`-классов; встретились только `FACE_MALE`/`FACE_FEMALE`. На ранее присланной откровенной иллюстрации нашёл два `FEMALE_BREAST_EXPOSED` (0.811 и 0.678). На трёх ранее названных допустимыми иллюстрациях открытых интимных зон не нашёл (были `*_COVERED` и `BELLY_EXPOSED`). Текущий NSFWJS на том же видео дал `Porn=0.9564` на втором из восьми кадров. Это локальное наблюдение на пяти файлах, **не** оценка точности модели и **не** проверка скорости/памяти на VPS.

Следующий шаг — прогнать Marqo на тех же файлах, затем собрать больший вручную размеченный набор, включая аниме, мемы и обычные стримовые клипы. Для видео сохранять покадровые ответы, максимум, время и RSS памяти. Выбирать модель/правило лишь если откровенные примеры остаются со спойлером, а допустимые перестают ошибочно скрываться.
